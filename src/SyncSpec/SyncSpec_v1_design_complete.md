# SyncSpec-v1
## Synchronized Lossless Speculative Decoding for Long-Context Summarization

> **Status:** Living design document — Revision v1.1 (2026-09-03)  
> **Purpose:** Working specification for iterative research, training, implementation, ablation, evaluation, and paper formulation.  
> **Guarantee target:** Lossless speculative decoding relative to the full-context target model.  
> **Revision note:** v1.1 adds the missing formal model contract, two-level adaptive draft/verify budgeting, exact algorithms, training objectives, batch-aware serving, implementation interfaces, success gates, novelty boundaries, failure modes, and reproducibility checklist.

---

# 1. Research goal

We aim to design a **cross-phase, synchronized speculative decoding framework** for long-context text summarization.

The method should jointly improve:

1. long-context draft efficiency,
2. candidate generation,
3. candidate selection,
4. speculative window allocation,
5. target verification efficiency,
6. scalability across context length and batch size,

while preserving the standard speculative decoding guarantee:

\[
P_{\text{SyncSpec}}(Y\mid X)=P_T(Y\mid X).
\]

The central principle is:

\[
\boxed{
\text{Generate broadly, select source-coherently, and verify only as far as expected utility justifies.}
}
\]

The system should optimize not raw acceptance rate, but:

\[
\boxed{
U_t=
\frac{\mathbb E[\text{committed target tokens}]}
{T_{\rm draft}+T_{\rm selection}+T_{\rm verify}+T_{\rm system}}
}
\]

or equivalently minimize:

\[
\boxed{
\mathrm{CTC}_t=
\frac{
T_{\rm draft}+T_{\rm selection}+T_{\rm verify}+T_{\rm system}
}{
\mathbb E[\text{committed target tokens}]
}
}
\]

where **CTC** denotes *Committed Token Cost*.

---

# 2. Main motivation

The method is motivated by several observations already established in prior work.

## 2.1 Long-context speculative decoding has multiple simultaneous bottlenecks

LongSpec identifies three major problems when extending speculative decoding to long contexts:

- draft KV-cache growth with context length,
- mismatch between short-context draft training and long-context inference,
- inefficiency of conventional tree verification with long-context optimized attention kernels.

This motivates a long-context-specific drafter architecture and training regime.

## 2.2 Diffusion drafting reduces sequential proposal latency

DFlash-style block diffusion drafting generates an entire speculative block in parallel rather than autoregressively producing \(K\) draft tokens.

Conceptually:

\[
T_D^{AR}(K)\approx K\,T_{\rm step},
\]

while block diffusion aims for:

\[
T_D^{diff}(K)\approx T_{\rm block}.
\]

This changes the bottleneck structure of speculative decoding.

## 2.3 Diffusion candidate recall can be much higher than top-1 accuracy

DFlash2 motivates a key distinction:

\[
\text{candidate generation quality}
\neq
\text{candidate selection quality}.
\]

A correct future target token may already exist in the diffusion top-\(M\) set even if the diffusion top-1 choice is wrong.

This suggests the decomposition:

\[
\boxed{
\text{Diffusion} \rightarrow \text{high candidate recall}
}
\]

followed by:

\[
\boxed{
\text{Lightweight selector} \rightarrow \text{high path precision}.
}
\]

## 2.4 Summarization provides a free source-side lexical resource

Long-document summarization frequently reuses or preserves:

- named entities,
- organizations,
- dates,
- numbers,
- technical terms,
- domain phrases,
- locally copied spans.

Therefore source n-grams can provide cheap evidence for disambiguating candidates already generated by the diffusion drafter.

The intended role of n-grams is **not** to replace the drafter.

Instead:

\[
\boxed{
\text{Source n-grams rerank diffusion candidates only.}
}
\]

## 2.5 Verification is expensive and fixed draft windows are suboptimal

Target verification can dominate speculative-decoding runtime, especially when many speculative suffix tokens are rejected.

A fixed draft window:

\[
K=\text{constant}
\]

is therefore generally suboptimal.

The useful quantity is the probability that a speculative prefix survives verification:

\[
S_j=P(A\ge j),
\]

where \(A\) is the accepted-prefix length.

This motivates adaptive verification.

## 2.6 Runtime-optimal speculation depends on system regime

The optimal speculative budget depends on:

\[
L,\quad B,\quad \text{hardware},\quad T_D,\quad T_V,
\]

where:

- \(L\): current context length,
- \(B\): batch size or concurrency,
- \(T_D\): draft cost,
- \(T_V\): verification cost.

Therefore adaptive window size should **not** be trained directly as a hardware-specific class label.

Instead:

\[
\boxed{
\text{learn acceptance probability, derive budget analytically from measured cost.}
}
\]

# 3. Final SyncSpec-v1 decomposition

The current method is:

\[
\boxed{
\begin{aligned}
\textbf{SyncSpec-v1}=
&\text{Exact full-context target prefill}\\
+&\text{Long-context target-memory reuse}\\
+&\text{Parallel diffusion candidate generation}\\
+&\text{Source-coherent candidate selection}\\
+&\text{Prefix-survival modeling}\\
+&\text{Cost-optimal adaptive verification}\\
+&\text{Batch/context-aware execution profiles}\\
+&\text{Exact target verification}.
\end{aligned}
}
\]

The conceptual responsibilities are:

| Component | Primary objective |
|---|---|
| Diffusion drafter | Candidate recall |
| Local coherence selector | Intra-block consistency |
| Source n-gram signal | Source-supported lexical coherence |
| Survival head | Acceptance uncertainty estimation |
| Analytical controller | Runtime utility optimization |
| Target verifier | Exactness / losslessness |

# 4. Complete inference pipeline

At speculative round \(t\), maintain:

\[
\mathcal S_t=
\{
KV_t^T,\,
h_t^T,\,
\mathcal I_X,\,
M_X,\,
\mathcal H_t,\,
C_{\rm hw}
\}.
\]

Where:

- \(KV_t^T\): full target KV cache,
- \(h_t^T\): current target hidden/feature state,
- \(\mathcal I_X\): source n-gram index,
- \(M_X\): source memory bank for the drafter,
- \(\mathcal H_t\): acceptance/runtime history,
- \(C_{\rm hw}\): hardware/runtime profiling table.

Pipeline:

```text
                         SOURCE X
                            │
                  ┌─────────▼─────────┐
                  │ Exact Target      │
                  │ Full Prefill      │
                  └─────────┬─────────┘
                            │
                   Full Target KV
                            │
            ┌───────────────┴────────────────┐
            │                                │
   Target Feature Memory              Source n-gram Index
            │                                │
            └───────────────┬────────────────┘
                            │
                     PRE-DRAFT GATE
                AR / speculation profile
                            │
               ┌────────────▼────────────┐
               │ Long-Context Diffusion  │
               │ K_max tokens parallel   │
               └────────────┬────────────┘
                            │
                 Top-M candidates/position
                            │
               ┌────────────▼────────────┐
               │ Source-Coherent         │
               │ Candidate Selector      │
               └────────────┬────────────┘
                            │
                     Candidate Path
                            │
               ┌────────────▼────────────┐
               │ Prefix-Survival Head    │
               │ S_1 ... S_Kmax          │
               └────────────┬────────────┘
                            │
                  COST CONTROLLER
                  choose K_verify
                            │
               ┌────────────▼────────────┐
               │ Exact Target Verify     │
               │ FULL Original Context   │
               └────────────┬────────────┘
                            │
                Accept Prefix + Correction
                            │
                  Acceptance / Latency
                            └──────────────↺
```

# 5. Phase 0 — Exact full-context target prefill

The target model always receives the full source:

\[
X=x_1,\ldots,x_L.
\]

Compute:

\[
(H^T,KV^T)=T(X).
\]

No approximation is allowed on the target path.

The target path must not use:

- semantic source pruning,
- lossy source compression,
- approximate target KV eviction,
- approximate sparse target context.

This preserves:

\[
p_T(y_t\mid X,y_{<t}).
\]

Exact optimized kernels such as FlashAttention may still be used.

---

# 6. Phase 0A — Build source n-gram index

Use token IDs from the target tokenizer.

Build n-gram indices for:

\[
n\in\{2,3,4,5,6\}.
\]

A compact representation may map:

```text
(prefix_hash) -> [(next_token_id, count, positions)]
```

Example:

```text
Department of -> Defense
of Defense -> announced
Department of Defense -> announced
```

The index is created once per input document.

The n-gram store is not a separate drafter.

Its only role is to score candidates already proposed by the diffusion model.

---

# 7. Phase 0B — Build long-context source memory

Partition:

\[
X=C_1,\ldots,C_N.
\]

Initial chunk size:

\[
|C_i|=128 \text{ tokens}.
\]

Possible ablations:

\[
64,\;128,\;256.
\]

From selected target layers:

\[
\mathcal L_T=\{l_1,\ldots,l_r\},
\]

compute chunk descriptors:

\[
m_i=
P_M
\left[
\operatorname{Pool}
\left(
H^T_{\mathcal L_T}(C_i)
\right)
\right].
\]

The memory bank is:

\[
M_X=\{m_1,\ldots,m_N\}.
\]

This is drafter-only memory.

It does not replace the target KV cache.

# 8. Phase 1 — Pre-draft execution gate

There must be a decision before paying draft cost.

Initial action space:

\[
a_t^{pre}\in
\{
AR,\,
D_{16}
\}.
\]

Later:

\[
\{
AR,\,
D_8,\,
D_{16},
D_{24}
\}.
\]

Possible features:

\[
f_t^{pre}=
[
L_t,\,
B_t,\,
H_t^T,\,
A_{t-1},\,
\bar A_t,\,
T_D,\,
T_V,\,
m_t^{ngram}
].
\]

Where:

- \(L_t\): current context length,
- \(B_t\): current batch/concurrency,
- \(H_t^T\): target next-token entropy from the latest target call,
- \(A_{t-1}\): previous accepted length,
- \(\bar A_t\): EMA acceptance,
- \(m_t^{ngram}\): longest source n-gram match.

The first implementation should use a simple rule/profile lookup rather than a large neural policy.

AR fallback is mandatory.

\]

# 11. Draft block formulation

At committed target position \(t\):

\[
[
y_t,
MASK,
MASK,
\ldots,
MASK
].
\]

Initial maximum block:

\[
\boxed{K_{\max}=16}.
\]

Use one consistent anchor convention for both training and inference.

Recommended initial setting:

```text
sample_from_anchor = True
```

The physical block has \(K_d+1\) slots: the first slot is the last committed
target token and the remaining \(K_d\) slots are masked future positions. The
public drafter output removes slot zero, so \(K_d\) remains the number of
proposal tokens exposed to selector/verifier.

---

# 12. Target feature conditioning

Select several target layers:

\[
\mathcal L_T=
\{l_1,\ldots,l_r\}.
\]

Pilot:

\[
r=3.
\]

Full version:

\[
r=5.
\]

Fuse current target features:

\[
f_t=
P_F
[
h_t^{l_1};
h_t^{l_2};
\ldots;
h_t^{l_r}
].
\]

For every draft layer \(d\):

\[
K_d^{cond}=W_{K,d}f_t,
\]

\[
V_d^{cond}=W_{V,d}f_t.
\]

The target conditioning should persist through all draft layers rather than only the input layer.

The drafter sees:

\[
\boxed{
\text{local high-resolution generated prefix}
+
\text{selected long-range source memory}.

\[
W=256
\]

\[

# 14. Initial source-memory retrieval

Use a lightweight hybrid score:

\[
score(C_i)
=
\lambda_h
\cos(P_q h_t^T,m_i)
+
\lambda_n
I(C_i\text{ contains current n-gram match}).
\]

Then:

\[
\mathcal R_t=
TopR_i(score(C_i)).
\]

If the current output suffix has a source match, prioritize source chunks containing the match.

If not, rely primarily on target-anchor/chunk similarity.

This retrieval is allowed to be imperfect because it only affects the drafter.

---

# 15. Dynamic causal convolution

Use a small causal dependency mechanism similar in spirit to DFlash2.

For position \(j\):

\[
\tilde h_j
=
\alpha_j\odot h_j+
\beta_j\odot h_{j-1}.
\]

The mixing coefficients are predicted dynamically from hidden representations.

Initial settings:

\[
kernel\_size=2,
\]

\[
group\_size=16.
\]

Recommended block ordering:

```text
Attention
  ↓
Dynamic Causal Convolution
  ↓
MLP
```

This increases local coherence without converting the drafter back into a fully autoregressive model.

---

# 16. Diffusion output as a candidate lattice

For each speculative position:

\[
\ell_j\in\mathbb R^{|V|}.
\]

Do not immediately choose:

\[
\arg\max_v \ell_j(v).
\]

Keep:

\[
\mathcal C_j=TopM(\ell_j).
\]

Initial:

\[
\boxed{M=16}.
\]

The whole speculative block is:

\[
\mathcal C_1,\ldots,\mathcal C_{K_{\max}}.
\]

The diffusion drafter is explicitly optimized for:

\[
\boxed{\text{candidate Recall@M}}
\]

rather than only Recall@1.

---

# 17. Source-Coherent Candidate Selector

The selector scores candidate:

\[
v\in\mathcal C_j.
\]

Use:

\[
\boxed{
s_j(v)
=
\ell_j(v)
+
\lambda_c C_\phi(y_{j-1},v,h_j)
+
g_j\lambda_n R_X(v)
}
\]

with three terms.

## 17.1 Unary score

\[
\ell_j(v)
\]

comes from the diffusion drafter.

## 17.2 Local predecessor coherence

Use a low-rank bilinear compatibility:

\[
C_\phi(u,v,h_j)
=
\left(
E_p(u)\odot P_hh_j
\right)^T
E_s(v).
\]

Recommended selector rank:

Pilot:

\[
128.
\]

Full:

\[
256.
\]

## 17.3 Source n-gram evidence

Let the already selected path end with:

\[
z=(y_{j-m},\ldots,y_{j-1}).
\]

Find the longest matching suffix in the source.

Define:

\[
m^*
=
\max\{
m:
z\text{ occurs in }X
\}.
\]

Candidate score:

\[
R_X(v)
=
\log(1+count_X(z\rightarrow v))
+
\lambda_{loc}L_X(v).
\]

Where \(L_X(v)\) gives a continuity bonus if the candidate extends a previously aligned source span.

This distinguishes simple frequency from coherent source continuation.

---

# 18. Learned source n-gram gate

Do not use a constant source prior.

Predict:

\[
g_j=
\sigma(
MLP(
m^*,
count,
location\_continuity,
unary\_margin,
coherence\_margin
)
).
\]

Interpretation:

\[
g_j\approx0
\]

means source n-gram evidence is unreliable.

\[
g_j\approx1
\]

means source continuation is strong.

This should allow the same selector to behave differently on:

- CNN/DM,
- GovReport,
- Multi-News,
- QMSum,
- XSum,

without hard-coding dataset identity.

---

# 19. Candidate path selection

V1 should use a sequential tiny selector over the top-\(M\) candidate sets.

At each position:

\[
q_j(v)
=
softmax_{\mathcal C_j}
s_j(v).
\]

### Greedy mode

\[
\hat y_j=\arg\max_v q_j(v).
\]

### Stochastic proposal mode

\[
\hat y_j\sim q_j.
\]

The heavy diffusion forward remains parallel.

Only the lightweight selector is sequential.

A later extension can test:

- beam search,
- Viterbi path decoding,
- shallow lattice search.

Do not make these required for V1.

---

# 20. Prefix-survival head

For selected path:

\[
\hat y_1,\ldots,\hat y_{K_{\max}},
\]

predict:

\[
\boxed{
S_j=P(A\ge j).
}
\]

Use position features:

\[
f_j=
[
h_j^D,\,
\log q_j(\hat y_j),\,
margin_j,\,
R_X(\hat y_j),\,
g_j,\,
m_j,\,
j
].
\]

Predict hazard:

\[
r_j=MLP(f_j),
\]

\[
h_j=\sigma(r_j).
\]

Then:

\[
\boxed{
S_j=
\prod_{i=1}^{j}(1-h_i)
}
\]

which guarantees:

\[
S_1\ge S_2\ge\cdots\ge S_K.
\]

The survival head estimates acceptance uncertainty.

It does **not** directly predict \(K\).

---

# 21. Adaptive verification budget

Given survival probabilities:

\[
S_1,\ldots,S_{K_{\max}},
\]

the expected accepted tokens when verifying \(k\) candidates is:

\[
E[A_k]
=
\sum_{j=1}^{k}S_j.
\]

Approximate committed progress:

\[
C(k)
\approx
1+\sum_{j=1}^{k}S_j.
\]

The extra \(1\) corresponds to the correction/bonus target token under standard speculative decoding.

---

# 22. Hardware/runtime profiling

Measure:

\[
T_{\rm AR}(L,B),
\]

\[
T_D(K,L,B),
\]

\[
T_S(K),
\]

\[
T_V(k,L,B).
\]

Where:

- \(T_D\): draft latency,
- \(T_S\): selector latency,
- \(T_V\): target verification latency.

Initial profile grid:

\[
L\in\{2K,4K,8K,16K,32K\},
\]

\[
B\in\{1,4,8,16,32\},
\]

\[
k\in\{2,4,6,8,12,16\}.
\]

Use lookup + interpolation rather than a learned latency model.

# 23. Analytical adaptive-\(K\) rule

Post-draft controller chooses:

\[
\boxed{
k_t^*
=
\arg\max_{k\in\mathcal K}
\frac{
1+\sum_{j=1}^{k}S_j
}{
T_D+
T_S+
T_V(k,L,B)
}
}
\]

with:

\[
\mathcal K=
\{2,4,6,8,12,16\}.
\]

This directly maximizes expected committed tokens per unit time.

Do not train a \(K\)-classification head.

---

# 24. Marginal stopping interpretation

Let:

\[
C_k=
1+\sum_{j=1}^{k}S_j,
\]

\[
T_k=T_D+T_S+T_V(k).
\]

Extending from \(k\) to \(k+1\) is beneficial if:

\[
\frac{C_k+S_{k+1}}
{T_k+\Delta T_{k+1}}
>
\frac{C_k}{T_k}.
\]

Equivalent:

\[
\boxed{
S_{k+1}
>
U_k\,\Delta T_{k+1}
}
\]

where:

\[
U_k=\frac{C_k}{T_k}.
\]

Interpretation:

> Verify one more speculative token only if its survival probability exceeds the runtime opportunity cost created by extending verification.

---

# 25. AR fallback

AR is a real action.

Estimate:

\[
U_{\rm AR}
=
\frac{1}
{T_{\rm AR}(L,B)}.
\]

If:

\[
\hat U_{\rm spec}
<
(1+\epsilon)U_{\rm AR},
\]

use autoregressive decoding.

Initial safety margin:

\[
\epsilon\in[0.03,0.05].
\]

This is an engineering default, not a fixed theoretical constant.

---

# 26. Exact target verification

The target verifier always uses:

\[
\boxed{
KV^T(X,y_{<t})
}
\]

with the full original source context.

The selected long-context memory used by the drafter must **never** replace the full target KV during verification.

---

# 27. Greedy exact mode

For candidate tokens:

\[
\hat y_1,\ldots,\hat y_k,
\]

target computes:

\[
y_j^T=
\arg\max p_T(\cdot\mid X,y_{<t},\hat y_{<j}).
\]

Accept the longest matching prefix.

On first mismatch:

- discard speculative suffix,
- commit target token.

At the algorithmic level:

\[
\boxed{
Y_{\rm SyncSpec}
=
Y_{\rm Target-AR}.
}
\]

---

# 28. Stochastic exact mode

The sequential selector must define a normalized proposal:

\[
q_j(v).
\]

Standard speculative acceptance:

\[
a_j=
\min
\left(
1,
\frac{p_j(\hat y_j)}
{q_j(\hat y_j)}
\right).
\]

If rejected:

\[
p'_j(v)
\propto
[p_j(v)-q_j(v)]_+.
\]

The proposal may have support only on top-\(M\) candidates as long as it is a valid normalized proposal distribution.

This preserves the target distribution under standard speculative correction sampling.

---

# 29. Runtime feedback loop

After each target verification, observe:

\[
A_t,
T_D^t,
T_S^t,
T_V^t.
\]

Update acceptance EMA:

\[
\bar A_t=
(1-\eta)\bar A_{t-1}
+
\eta A_t.
\]

Update latency profile/EMA similarly.

Update target KV only with committed tokens.

The next speculative round starts from the new committed endpoint.

# 35. Diffusion training loss

If teacher logits are available:

\[
\mathcal L_D
=
\sum_{j=1}^{K}
w_j
D_{KL}
(
p_T^j
\Vert
q_D^j
).
\]

Pilot version:

\[
\mathcal L_D
=
\sum_j
w_j
CE(q_D^j,y_j^T).
\]

Initial position weighting:

\[
w_j=
\exp
\left(
-\frac{j-1}{\gamma}
\right).
\]

Do not suppress suffix losses too aggressively because high top-\(M\) recall at later positions may still be valuable to the selector.

# 36. Long-context positional training

Adopt an Anchor-Offset-style strategy.

For a training sequence with local positions:

\[

\]

\[

Suggested curriculum:

\[

\rightarrow

\rightarrow
16K
\rightarrow
32K.
\]

Use a mixture of:

- real long summarization documents,
- shorter documents with position offsets.

# 37. Stage 2 — Source-Coherent Selector training

Start only after diffusion Recall@16 is sufficiently high.

Initially freeze the diffusion backbone.

For each draft position:

\[

=

\log

(

\mid
\mathcal C_j,
y_{j-1},
X

Trainable:

This keeps generation and selection errors separate.

\rightarrow

\rightarrow

# 40. Stage 3 — On-policy survival training

Run the current pipeline:

```text
diffusion
  ↓
source-coherent selector
  ↓
target verification
```

\[

Create labels:

\[

Train survival:

\[
\mathcal L_{\rm surv}
=
-\sum_j

+

A hazard-based likelihood is also acceptable.

# 60. Lossless guarantee

The drafter may use:

\[

Y'\mid
R(X),y_{<t}
),
\]

where \(R(X)\) may be reduced, selected, or approximate.

Y'\mid
X,y_{<t}
)
\]

on the complete original context.

Therefore the draft-side approximation affects only:

- acceptance rate,
- speculative efficiency,
- latency.

It does not determine final correctness.

With standard speculative acceptance/correction:

\[

=

}

# 61. One-sentence method description

> **SyncSpec is a lossless long-context speculative-decoding framework that uses a target-conditioned block-diffusion drafter to generate high-recall future-token candidate sets, reranks them with lightweight local coherence and source n-gram evidence, predicts speculative-prefix survival, and analytically chooses a hardware-aware verification budget to maximize committed-token throughput while the target always performs exact verification over the complete original context.**

# 64. Formal notation

Let:

- \(X=(x_1,\ldots,x_L)\): full source document and instruction prompt;
- \(Y=(y_1,\ldots,y_T)\): generated summary;
- \(T\): frozen target/verifier model;
- \(D_\theta\): trainable block-diffusion drafter;
- \(S_\phi\): source-coherent candidate selector;
- \(G_\psi\): prefix-survival estimator;
- \(\mathcal I_X\): source n-gram index;
- \(M_X\): compressed source memory bank used only by the drafter;
- \(B_t\): effective serving batch size at speculative round \(t\);
- \(L_t=L+t\): current target context length;
- \(K_d\): number of future positions produced by the diffusion drafter;
- \(K_v\le K_d\): number of selected proposal tokens actually sent to the target verifier;
- \(M\): number of unary candidates retained per draft position;
- \(A_t\): true accepted speculative-prefix length;
- \(S_{t,j}=P(A_t\ge j)\): prefix-survival probability.

A speculative action is:

\[
a_t=(K_d,K_v,R),
\]

where \(R\) is the number of long-source memory chunks exposed to the drafter.

For SyncSpec-v1, \(R\) may initially be fixed. The first truly adaptive axes are:

\[
\boxed{
K_d \quad\text{and}\quad K_v.
}
\]

This distinction is important:

- reducing \(K_d\) saves **draft compute**;
- reducing \(K_v\) saves **target verification compute**;
- \(K_v\) can only be chosen after draft confidence is available;
- \(K_d\) must be chosen before paying the diffusion forward cost.

---

# 65. Two-level budget allocation

A single adaptive-\(K\) variable is insufficient for a block-parallel drafter.

SyncSpec therefore uses:

\[
\boxed{
\text{coarse pre-draft budget}
+
\text{fine post-draft verification budget}.
}
\]

## 65.1 Pre-draft budget

Before executing the drafter, choose:

\[
K_d\in\mathcal K_D.
\]

Recommended first profile set:

\[
\mathcal K_D=\{8,16\}.
\]

Add \(24\) only if \(K_d=16\) frequently saturates with all tokens accepted.

The pre-draft controller may also choose:

\[
K_d=0,
\]

which means direct target AR decoding.

## 65.2 Post-draft budget

After diffusion, source-aware reranking, and survival prediction:

\[
K_v\in\mathcal K_V(K_d),
\qquad
K_v\le K_d.
\]

For \(K_d=16\), a practical discrete set is:

\[
\mathcal K_V(16)=\{2,4,6,8,12,16\}.
\]

This avoids irregular arbitrary lengths while still giving enough adaptation resolution.

# 66. Pre-draft utility estimator

The post-draft survival head cannot decide whether drafting itself was worth executing because draft cost has already been paid.

Therefore SyncSpec needs a **cheap prior survival estimate** before the diffusion forward.

The first implementation should not train another large controller. Use a calibrated table / lightweight state model:

\[
\tilde S_{t,j}
=
F_{\rm prior}
(
K_d,
L_t,
B_t,
H_t^T,
A_{t-1},
\bar A_t,
m_t^{ng},
d_t
),
\]

where:

- \(H_t^T\): target entropy available from the latest target call;
- \(A_{t-1}\): previous accepted length;
- \(\bar A_t\): request-level EMA accepted length;
- \(m_t^{ng}\): longest current output suffix matched in the source;
- \(d_t\): dataset-independent draft confidence history.

A practical V1 implementation is **binned empirical calibration** rather than a neural model:

```text
(context-bin, batch-bin, previous-accept-bin, ngram-bin, entropy-bin)
    -> mean prefix-survival curve
```

If data sparsity becomes a problem, replace the table with a tiny MLP.

---

# 67. Pre-draft action rule

For profile \(K_d\), estimate:

\[
\hat C^{pre}(K_d)
=
1+
\sum_{j=1}^{\hat K_v(K_d)}
\tilde S_{t,j},
\]

where \(\hat K_v(K_d)\) is the verification budget predicted from the prior survival curve.

The estimated speculative utility is:

\[
\hat U_t^{pre}(K_d)
=
\frac{
\hat C^{pre}(K_d)
}{
T_D(K_d,L_t,B_t)
+
\hat T_S(K_d)
+
T_V(\hat K_v,L_t,B_t)
}.
\]

AR utility is:

\[
U_t^{AR}
=
\frac{1}
{T_{AR}(L_t,B_t)}.
\]

Choose:

\[
K_d^*
=
\arg\max_{K_d\in\{0,8,16\}}
\hat U_t^{pre}(K_d),
\]

with \(K_d=0\) representing AR.

Use a safety margin:

\[
\hat U_t^{pre}(K_d)
>
(1+\epsilon)U_t^{AR}
\]

before enabling speculation.

This makes slowdown bounded: when the speculative profile is not expected to pay for itself, SyncSpec falls back to target AR.

# 68. Drafter architecture — precise module topology

The recommended SyncSpec-v1 drafter is a **same-width shallow block model**.

For the first implementation:

\[
d_D=d_T,
\]

so the target embedding and LM head can be reused without an additional output bottleneck.

The model contains \(N_D\) shallow decoder blocks.

A single draft block receives:

\[
H^{(0)}
\in
\mathbb R^{B\times (K_d+1)\times d_D}.
\]

Its context memory is:

\[
C_t
=
[
F_t^{anchor};
H_{t-W:t}^{T};
M_t^{src}
],
\]

where:

- \(F_t^{anchor}\): fused multi-layer target feature for the current committed endpoint;
- \(H_{t-W:t}^{T}\): ring buffer of recent target hidden states for committed output tokens;
- \(M_t^{src}\): selected long-source chunk descriptors.

Thus the drafter does **not** require a full independent source KV cache.

---

# 69. Recommended draft layer

Each draft layer \(l\) is:

```text
Input H_l
  │
  ├─ RMSNorm
  │
  ├─ Bidirectional block self-attention over K_d+1 physical slots
  │
  ├─ residual
  │
  ├─ grouped dynamic causal convolution
  │
  ├─ RMSNorm
  │
  ├─ cross-attention to target-derived context memory C_t
  │
  ├─ residual
  │
  ├─ grouped dynamic causal convolution
  │
  ├─ RMSNorm
  │
  └─ MLP
       │
       └─ residual -> H_{l+1}
```

The self-attention over the future block is non-causal / bidirectional, preserving the main DFlash advantage.

The local convolution supplies cheap directional dependence.

Cross-attention supplies source and target state without requiring a full drafter prefill.

---

# 70. Target-derived context memory

Use two temporal resolutions.

## 70.1 Recent output memory

Keep a fixed ring buffer:

\[
H_{t-W:t}^{T}
\]

of target hidden states for the most recent committed output tokens.

This provides high-resolution local history while memory remains:

\[
O(W).
\]

Recommended initial:

\[
W=64\text{ or }128
\]

for implementation profiling, then ablate \(256\).

This is cheaper than maintaining a full draft KV cache for all previous source/output tokens.

## 70.2 Long source memory

For source chunks \(C_i\), compute descriptors once during target prefill:

\[
m_i=P_M(
\mathrm{Pool}(H^T[C_i])
).
\]

Only the selected \(R\) descriptors are cross-attended at a round.

Thus long-source cross-attention length is:

\[
R
\]

rather than \(L\).

Exact lexical source details that pooling may discard are separately available through the n-gram side channel.

This creates an intentional division of labor:

\[
\boxed{
\text{compressed memory} \rightarrow \text{semantic long-range evidence}
}
\]

\[
\boxed{
\text{n-gram index} \rightarrow \text{exact lexical evidence}.
}
\]

---

# 71. Source memory pooling choices

The initial source-memory implementation should be simple.

Baseline:

\[
m_i
=
P_M\left(
\frac1{|C_i|}
\sum_{x\in C_i}h_x^T
\right).
\]

Ablate later:

1. mean pooling;
2. mean + max pooling;
3. learned attention pooling;
4. two-vector chunk memory: semantic centroid + boundary/recent token vector.

Do not start with a complex chunk encoder. The memory path must remain cheaper than the compute it saves.

---

# 72. Source-memory retrieval contract

The retrieval module returns:

```python
selected_chunk_ids: IntTensor[B, R]
selected_memory: FloatTensor[B, R, d_D]
retrieval_scores: FloatTensor[B, R]
```

The retrieval score may combine:

\[
r_{t,i}
=
\alpha\cos(q_t,m_i)
+
\beta\,ngramHit(t,i)
+
\gamma\,positionPrior(i).
\]

For V1:

\[
\gamma=0
\]

unless profiling reveals a clear positional benefit.

Raw target attention may be logged as an analysis feature, but it should not be the primary supervision signal because earlier project experiments found grounding/attention heuristics insufficiently robust for predicting speculative success.

# 73. Block-parallel prediction contract

For a chosen draft budget \(K_d\), construct:

\[
Z_t=
[
e(y_t),
e([MASK]_1),
\ldots,
e([MASK]_{K_d})
].
\]

Here \(y_t\) is the last committed target token (the source prompt's final
token for the first block). The target hidden state at \(y_t\), together with
the recent target-hidden ring buffer, is passed as context. The model runs on
all \(K_d+1\) physical slots, but slot zero is an anchor and is removed from
the public output and all future-token losses.

The drafter returns:

```python
unary_logits: FloatTensor[B, K_d, V]
draft_hidden: FloatTensor[B, K_d, d_D]
```

and candidate extraction returns:

```python
candidate_ids: IntTensor[B, K_d, M]
candidate_logits: FloatTensor[B, K_d, M]
```

with:

\[
M=16.
\]

All subsequent selection operates only on this small candidate lattice.

---

# 74. Candidate-recall-oriented diffusion objective

Standard KL/CE aligns the drafter to the target distribution but does not directly express the research goal:

\[
y_j^T\in TopM(q_D^j).
\]

Add an optional small top-\(M\) margin term.

Let:

- \(\ell_j^+\): logit of the target token;
- \(\ell_{j,(M+1)}\): \((M+1)\)-th largest non-target logit.

Define:

\[
\mathcal L_{rank}
=
\sum_j
\max(
0,
\mu-\ell_j^+
+\ell_{j,(M+1)}
).
\]

Then:

\[
\boxed{
\mathcal L_D
=
\mathcal L_{KL/CE}
+
\lambda_{rank}\mathcal L_{rank}.
}
\]

Use a small \(\lambda_{rank}\) and treat this as an ablation.

The KL component preserves distributional alignment; the margin term explicitly targets candidate recoverability.

---

# 75. Position weighting

Prefix positions have higher computational value because the first rejection discards the remaining chain.

However, SyncSpec should not over-penalize suffix positions because DFlash2-style selection can recover non-top-1 candidates.

Recommended first objective:

\[
w_j=
\exp(-(j-1)/\gamma),
\]

with a moderate \(\gamma\), plus an ablation against:

- uniform weighting;
- D-PACE-style confidence weighting;
- entropy-driven curriculum inspired by EDSD.

The paper should avoid claiming a new training curriculum unless an ablation demonstrates a real gain over these established alternatives.

---

# 76. Source-coherent selector — serving-valid probability

For each position \(j\), the selector sees:

\[
\mathcal C_j=\{v_{j,1},\ldots,v_{j,M}\}.
\]

Score:

\[
s_j(v)
=
u_j(v)
+
\lambda_c C_\phi(y_{j-1},v,h_j)
+
g_j\lambda_n R_X(v),
\]

where \(u_j(v)\) is the unary draft score.

Define the actual proposal distribution:

\[
\boxed{
q_j(v)
=
\frac{\exp(s_j(v)/\tau_q)}
{\sum_{u\in\mathcal C_j}
\exp(s_j(u)/\tau_q)}
}
\]

for \(v\in\mathcal C_j\), and:

\[
q_j(v)=0
\]

outside the candidate set.

This normalized \(q_j\) must be retained for exact stochastic speculative acceptance.

In greedy mode, choose:

\[
\hat y_j=\arg\max q_j.
\]

In stochastic mode, sample:

\[
\hat y_j\sim q_j.
\]

---

# 77. Selector training objective

There are two distinct goals.

## 77.1 Greedy-alignment training

For target-generated greedy trajectories:

\[
\mathcal L_{sel}^{hard}
=
-\log q_j(y_j^T)
\]

only when:

\[
y_j^T\in\mathcal C_j.
\]

If the target token is absent, the selector cannot recover it. The scientifically clean default is therefore:

\[
mask_j=
\mathbf1[y_j^T\in\mathcal C_j].
\]

Then:

\[
\mathcal L_{sel}^{hard}
=
-\sum_j mask_j\log q_j(y_j^T).
\]

Target-injection into Top-\(M\), as used by experimental public DFlash2 training code, should be an implementation ablation rather than the main reported metric.

## 77.2 Distribution-alignment training

If target logits are cached, normalize the target distribution over the candidate set:

\[
p_{T,j}^{\mathcal C}(v)
=
\frac{p_{T,j}(v)}
{\sum_{u\in\mathcal C_j}p_{T,j}(u)}.
\]

Train:

\[
\mathcal L_{sel}^{KD}
=
D_{KL}
(
p_{T,j}^{\mathcal C}
\Vert
q_j
).
\]

Recommended full selector loss:

\[
\boxed{
\mathcal L_{sel}
=
\alpha\mathcal L_{sel}^{hard}
+
(1-\alpha)\mathcal L_{sel}^{KD}.
}
\]

This is especially important if exact stochastic decoding is evaluated.

---

# 78. Source n-gram feature vector

For candidate \(v\), compute a small fixed feature vector:

\[
\phi_{ng}(v)=
[
m^*,
\log(1+c),
\Delta p,
is\_contiguous,
is\_entity,
is\_number
].
\]

Where:

- \(m^*\): longest source suffix match length;
- \(c\): source continuation count;
- \(\Delta p\): distance from the most recent aligned source position;
- `is_contiguous`: whether \(v\) extends the same source occurrence;
- `is_entity`, `is_number`: optional tokenizer-level / lightweight lexical flags.

The first implementation should avoid external NER inference; use cheap lexical features only.

The n-gram gate is:

\[
g_j=\sigma(MLP(\phi_{ng},margin_j,h_j^{small})).
\]

It is trained through the selector objective, not through a separate language-model objective.

---

# 79. N-gram index implementation

Recommended structure:

```python
class SourceNgramIndex:
    # maps suffix hashes to compact continuation records
    table[n][prefix_hash] -> {
        next_token_ids: IntTensor[Kc],
        counts: IntTensor[Kc],
        positions: compressed position list / last position
    }
```

Implementation rules:

1. tokenize once with the target tokenizer;
2. exclude instruction/system tokens from the source lexical index;
3. maintain a separate optional index for already committed summary tokens;
4. use longest-match backoff;
5. cap the number of stored continuations per prefix;
6. perform lookup on CPU if it stays below the latency budget; otherwise move compact tables to pinned memory / GPU hash structures.

V1 should use **source-only n-grams** in the main method. Summary-history n-grams are an ablation.

---

# 80. Prefix-survival target

For a realized proposal path:

\[
\hat y_{1:K_d},
\]

let \(A\) be the true longest accepted prefix.

Hard target:

\[
z_j=\mathbf1[A\ge j].
\]

The survival head predicts hazards:

\[
h_j\in(0,1)
\]

and:

\[
S_j=\prod_{i=1}^{j}(1-h_i).
\]

Hard BCE is:

\[
\mathcal L_{surv}^{hard}
=
-\sum_j
[
z_j\log S_j
+
(1-z_j)\log(1-S_j)
].
\]

---

# 81. Soft survival supervision for stochastic SD

For exact stochastic speculative decoding, each realized proposal token has acceptance probability:

\[
\alpha_j
=
\min\left(
1,
\frac{p_j(\hat y_j)}
{q_j(\hat y_j)}
\right).
\]

A useful lower-variance soft survival target is:

\[
\tilde S_j
=
\prod_{i=1}^{j}\alpha_i.
\]

Train:

\[
\mathcal L_{surv}^{soft}
=
\sum_j
BCE(S_j,\tilde S_j).
\]

Recommended:

- greedy main track: hard accepted-prefix labels;
- stochastic exact track: soft probability targets plus hard rollout calibration.

---

# 82. Survival features

The survival estimator should use evidence from every upstream phase:

\[
f_j=
[
h_j^D,
\log q_j(\hat y_j),
margin_j,
entropy(q_j),
g_j,
m_j^{ng},
continuity_j,
position_j,
K_d,
L_t^{bin},
B_t^{bin}
].
\]

This is a central synchronization point.

The source selector improves path quality **and** provides evidence to the survival estimator.

The survival estimator then controls the expensive target verification phase.

---

# 83. Post-draft cost-optimal verification

Once the draft has already run, \(T_D\) is a sunk cost for the current round.

The post-draft controller chooses \(K_v\) using:

\[
\boxed{
K_v^*
=
\arg\max_{k\le K_d}
\frac{
1+\sum_{j=1}^{k}S_j
}{
T_D(K_d,L_t,B_t)
+
T_S(K_d)
+
T_V(k,L_t,B_t)
}.
}
\]

Because \(T_D\) is constant with respect to \(k\) within this round, the decision mainly trades:

\[
\text{expected extra committed tokens}
\]

against:

\[
\text{extra verification latency}.
\]

The controller should operate only over a small discrete profile set to preserve batching regularity.

---

# 84. Batch-aware profile scheduler

Per-request adaptation can destroy kernel regularity if every request uses a different shape.

Therefore define a finite profile set:

\[
\mathcal P=
\{
AR,\,
(8,4),\,
(8,8),\,
(16,4),\,
(16,8),\,
(16,12),\,
(16,16)
\},
\]

where each pair is:

\[
(K_d,K_v).
\]

At each scheduler cycle:

1. requests choose a preferred profile;
2. requests with the same \(K_d\) are grouped for the diffusion forward;
3. after survival prediction, requests are regrouped by \(K_v\) if the engine permits;
4. if regrouping cost is too high, round \(K_v\) to the nearest supported batch profile;
5. include the measured regroup/scheduling cost in \(T_S\).

The paper must measure the controller under actual batched execution, not only replay individual requests offline.

---

# 85. Scheduler regularization

When two profiles have similar predicted utility, prefer the profile with the larger current queue.

A simple serving utility is:

\[
U^{serve}_t(p)
=
U_t(p)
-
\lambda_f C_{frag}(p),
\]

where \(C_{frag}\) estimates fragmentation / underfilled-batch cost.

For V1, a simpler deterministic rule is sufficient:

> If two profiles differ by less than \(\delta_U\), choose the profile with more requests already waiting.

This prevents adaptation from sacrificing GPU occupancy.

# 86. Exact inference algorithm

```text
Algorithm 1: SyncSpec-v1 Inference

Input:
    target T
    drafter D
    selector S
    survival head G
    source X
    hardware profile C_hw

1. Target full-prefill X.
2. Build:
       full target KV,
       source chunk memory M_X,
       source n-gram index I_X.
3. Initialize recent target-hidden ring buffer and runtime history.

while EOS not reached:

    4. Read current state:
           L_t, B_t, previous acceptance,
           target entropy, n-gram match state.

    5. PRE-DRAFT:
           estimate U_AR and U_pre(K_d) for supported K_d.
           choose AR or K_d.

    6. if AR:
           run one exact target step;
           commit target token;
           update target KV/history;
           continue.

    7. Retrieve R source-memory chunks.

    8. Run ONE block-parallel diffusion forward for one anchor plus K_d masked
       future slots.

    9. Keep Top-M unary candidates at every position.

   10. Sequential tiny selector:
           start from verified anchor;
           at each position:
               compute local transition score;
               query source n-gram evidence;
               compute n-gram gate;
               form normalized q_j over candidate set;
               choose/sample proposal token.

   11. Survival head predicts S_1 ... S_Kd.

   12. POST-DRAFT:
           choose K_v <= K_d maximizing expected
           committed-tokens / measured round latency.

   13. Target verifies proposal[1:K_v] using FULL target context.

   14. Apply exact speculative accept/reject:
           greedy longest-prefix mode
           OR
           stochastic rejection/residual correction.

    15. Commit accepted tokens + target correction/bonus token; the resulting
        final committed token becomes the next block's physical anchor.

   16. Roll back all uncommitted speculative target KV entries.

   17. Update:
           full target KV,
           recent target hidden ring buffer,
           n-gram/output history,
           acceptance EMA,
           runtime EMA / profile statistics.

return exact target-distributed summary
```

---

# 87. Target KV transaction semantics

Implementation must treat verification as a transaction.

Before verify:

```text
committed_target_kv_length = n
```

Target temporarily computes KV for \(K_v\) proposal positions.

After acceptance length \(A\):

- keep KV entries corresponding to committed accepted tokens;
- keep the target correction/bonus token as appropriate;
- discard KV corresponding to rejected speculative suffix.

The target KV must never retain state for uncommitted proposal tokens.

This is necessary both for correctness and reproducibility.

# 88. Training algorithm — Stage 0

```text
Algorithm 2: Target-Trajectory Collection

for each source document X:
    1. format the exact summarization prompt;
    2. run frozen target with the final intended decoding setup;
    3. save target-generated Y^T;
    4. save source token IDs and source boundaries;
    5. save selected target anchor hidden states, recent-hidden windows, and

    6. optionally save target logits / top-logits;
    7. build source n-gram metadata;
    8. generate random anchor indices for downstream training.
```

Important:

- use the same tokenizer and prompt template as final inference;
- do not mix human references into the draft alignment target;
- human references remain evaluation labels for summary quality, not draft supervision;
- maintain dataset train/validation/test separation before generating trajectories.

# 89. Training algorithm — Stage 1

```text
Algorithm 3: Diffusion Backbone Training

for each optimizer forward:
    select trajectory rows
    for each selected trajectory, sample up to N_a random eligible anchors
      (current + K_d future targets supervised and physical block fits)
    sample block budget K_d
    obtain the committed anchor token and target hidden/recent-hidden state
    obtain / retrieve source memory
    construct anchor + masked future block
    run block-parallel drafter with FlashAttention-first SDPA dispatch
      and efficient/math SDPA fallback
    exclude the physical anchor slot from supervision
    compute KL/CE target-alignment loss
    optionally compute Top-M rank-margin loss
    apply position weighting
    update only draft backbone + memory projections + dynamic conv
```

Recommended ordering:

1. start without source-memory cross-attention to reproduce a DFlash-like baseline;
2. add compressed source memory;
3. add Anchor-Offset / long-position training;
4. add top-\(M\) ranking auxiliary only if Recall@M remains the bottleneck.

This keeps debugging causal.

# 90. Training algorithm — Stage 2

```text
Algorithm 4: Source-Coherent Selector Training

freeze or low-LR the diffusion backbone

for each training anchor:
    run / load unary logits
    keep true serving Top-M candidate set
    compute predecessor-conditioned local scores
    compute source n-gram features
    compute learned n-gram gate
    normalize selector q_j over candidates

    if target token is inside Top-M:
        compute hard CE
        optionally compute candidate-restricted target KL
    else:
        mask selector loss at this position
        record candidate miss for diffusion Recall@M statistics

    gradually replace teacher predecessor with self-selected predecessor
```

The key separation is:

\[
\boxed{
\text{candidate miss} \rightarrow \text{drafter problem}
}
\]

\[
\boxed{
\text{wrong choice given candidate present} \rightarrow \text{selector problem}.
}
\]

# 91. Training algorithm — Stage 3

```text
Algorithm 5: On-Policy Survival Training

for each source X:
    run the actual current SyncSpec drafter + selector
    obtain proposal path and proposal probabilities q
    run exact target verification
    record:
        accepted length A
        target p on proposal tokens
        q on proposal tokens
        source n-gram features
        draft hidden features
        runtime profile

    create hard and/or soft survival labels
    update only survival head initially
```

The survival head must be trained on **self-conditioned proposal paths**, not teacher-forced paths.

Otherwise calibration at deployment will be optimistic.

# 93. Initial optimizer recipe

These are **engineering starting points**, not claims of optimality.

## Stage 1 — draft backbone

- optimizer: AdamW;
- precision: BF16 when supported;
- gradient clipping: 1.0;
- warmup: 2–5%;
- trainable parameters: drafter only;
- start LR search around \(5\times10^{-5}\) to \(2\times10^{-4}\);
- use token/anchor-count-based batching rather than document-count batching;
- validate Recall@M every fixed number of optimizer steps.

## Stage 2 — selector

- higher LR than backbone is usually reasonable;
- start around \(2\times10^{-4}\) to \(10^{-3}\);
- backbone frozen for the first selector experiments;
- early stop on **self-conditioned path accepted length**, not selector CE alone.

## Stage 3 — survival

- small MLP/head;
- start around \(10^{-4}\) to \(10^{-3}\);
- early stop on Brier score / ECE and downstream oracle-regret, not BCE alone.

All values must be tuned on validation traces.

# 94. Training data mixture policy

Do not use a single summarization dataset because n-gram usefulness and abstraction differ strongly by task.

Recommended stratified training mixture:

```text
copy-heavy / source-preserving:
    CNN/DM
    Multi-News

long structured:
    GovReport

highly abstractive:
    XSum

conversation / long dialogue:
    QMSum
```

Use either:

1. approximately balanced anchor counts per dataset; or
2. temperature-based sampling so CNN/DM does not dominate purely by size.

Record dataset identity for analysis, but do not feed dataset ID to the model in the main method.

The method should infer whether source lexical evidence is useful from the request state itself.

# 95. Target-decoding tracks

The project should maintain two separate correctness tracks.

## 95.1 Greedy exact track

Primary engineering track.

Benefits:

- easiest output-equivalence testing;
- deterministic accepted-prefix diagnostics;
- simpler debugging;
- directly relevant to many summarization deployments.

## 95.2 Stochastic exact track

Secondary but theoretically important.

Use a fixed target sampling configuration, e.g. temperature/top-p, and the exact proposal probability \(q_j\).

Validate distributional equivalence statistically.

Do not claim stochastic exactness from a selector that only outputs an unnormalized path score.

# 96. Exactness tests

## 96.1 Greedy

For every validation request:

```python
assert accelerated_token_ids == vanilla_target_token_ids
```

with the same:

- prompt;
- tokenizer;
- target precision;
- decoding parameters;
- EOS rule.

Because GPU kernels may be numerically nondeterministic, also provide a deterministic reference setting for correctness tests.

## 96.2 Sampling

Use repeated generations to compare accelerated and target-only distributions.

Possible diagnostics:

- token-frequency tests at controlled short prefixes;
- KL / TV distance on next-token samples;
- sequence-level statistic comparison;
- exact acceptance/residual-sampling unit tests on synthetic distributions.

The mathematical guarantee comes from the acceptance algorithm; empirical tests validate the implementation.

# 97. Unit-test suite

Before any large experiment, implement tests for:

1. source n-gram lookup correctness;
2. longest-match backoff;
3. candidate-set normalization;
4. selector \(q_j\) sums to 1;
5. candidate probability is unchanged by batching order;
6. survival monotonicity:
   \[
   S_1\ge S_2\ge\cdots;

10. target KV rollback after rejection;

12. AR fallback bypasses all drafter state changes.

# 102. Selector recovery metrics

Define candidate opportunity:

\[
O=
\mathbf1[y_j^T\in TopM].
\]

Selector recovery rate:

\[
RR
=
P(
\hat y_j=y_j^T
\mid
O=1,\,
\arg\max q_D\ne y_j^T
).
\]

This isolates whether the selector actually closes the Recall@M vs Recall@1 gap.

Also report:

\[
RR_{ng}
\]

for positions with source n-gram support and:

\[
RR_{\neg ng}
\]

without source support.

This is the key evidence for the summarization-specific contribution.

- dataset;

# 104. Adaptive-budget regret

Let oracle per-round utility be:

\[
U_t^*
=
\max_{K_d,K_v}
U_t(K_d,K_v).
\]

Controller regret:

\[
R_t
=
U_t^*-U_t(\hat K_d,\hat K_v).
\]

Report:

\[
\frac{\sum_t U_t(\hat a_t)}
{\sum_t U_t^*}
\]

or average normalized regret.

This is more informative than reporting only length-prediction accuracy.

The controller is successful if it captures most of the oracle headroom.

# 105. Research go/no-go gates

## Gate G0 — Diffusion selection headroom

Continue the source-aware selector only if a meaningful gap exists:

\[
Recall@16-Recall@1
\]

or oracle accepted-length gain is substantial.

## Gate G1 — Source recoverability

Continue n-gram reranking only if source features recover a meaningful fraction of wrong-top1 / correct-topM positions.

## Gate G2 — Adaptive budget headroom

Train survival/control only if oracle adaptive profiles beat the strongest fixed profile by a practically meaningful margin.

Recommended research threshold:

\[
\ge 10\%
\]

in at least important long-context or batched regimes.

## Gate G3 — Controller recoverability

The learned/calibrated controller should recover a large fraction of oracle gain.

Target:

\[
\ge 70\%\text{ of oracle headroom}
\]

as a reasonable initial goal.

## Gate G4 — End-to-end relevance

A component is kept only if its gain remains after including its own latency.

No component is justified by acceptance improvement alone.

# 109. Storage planning

The dominant disk cost can come from cached target hidden states.

Do not cache every target layer for every token unless necessary.

Prefer:

1. only selected target layers;
2. BF16/FP16 or tested lower-precision caches;
3. anchor-sampled features rather than full trajectory features when possible;
4. hybrid mode: generate target features once per epoch 0, then cache;
5. sharded files with metadata index.

Measure cache size on 100 samples before committing to the full dataset.

# 110. Compute planning

The research plan should intentionally delay the most expensive stage.

Order by cost:

```text
P0/P1/P2/P3/P4 using existing checkpoint
    << selector-only training
    << survival-head training
    << long-context diffusion fine-tuning
    << full serving sweep
```

The method should be terminated early if the corresponding oracle gate fails.

This is a core part of the research strategy, not merely an engineering convenience.

# 111. Novelty boundaries

The final paper must clearly separate adopted primitives from proposed contributions.

## 111.1 Established / adopted

Do not claim these as new:

- block-parallel diffusion drafting — DFlash;
- local dynamic convolution / predecessor-conditioned selector inspiration — DFlash2;
- confidence/adaptive-length motivation — DSpark/AdaFlash and adaptive SD;
- source/prompt n-gram utility — SSSD and retrieval-based SD;
- long-context draft-memory motivation / Anchor-Offset — LongSpec;
- full target verification for losslessness — standard speculative decoding.

## 111.2 Candidate SyncSpec contributions

Potential primary novelty claims are:

### N1 — Source-Coherent Diffusion Candidate Selection

Use exact source lexical evidence **inside the candidate-selection stage of a high-recall diffusion drafter**, rather than using n-grams as an independent proposer.

### N2 — Survival/Cost Decoupling

Learn:

\[
P(A\ge j)
\]

as a model property, but derive:

\[
(K_d,K_v)
\]

from measured hardware/runtime cost instead of directly learning a hardware-specific length label.

### N3 — Two-Level Adaptive Budgeting

Distinguish:

\[
K_d
\]

from:

\[
K_v,
\]

allowing the system to separately avoid unnecessary diffusion compute and unnecessary target verification compute.

### N4 — Cross-Phase Long-Context Co-Design

Compressed target-derived source memory, source lexical reranking, survival modeling, and cost allocation support one another while the target remains exact.

Only claim N4 strongly if interaction ablations demonstrate genuine synergy.

# 113. Paper-level hypothesis hierarchy

Separate background premises from new hypotheses.

## Established premises

Use literature rather than re-proving:

- long context creates draft-memory/training/verification problems;
- verification waste is expensive;
- acceptance varies across positions/requests/datasets;
- fixed speculation windows can be suboptimal;
- n-gram proposals are cheap where copy patterns exist;
- diffusion drafting is highly parallel.

## SyncSpec hypotheses requiring our experiments

### H1 — Recoverable diffusion candidate headroom

\[
Recall@16\gg Recall@1
\]

on summarization.

### H2 — Source evidence closes part of this gap

\[
RR_{source}
>
RR_{local-only}.
\]

### H3 — Adaptive \(K_d/K_v\) headroom exists

\[
U_{\rm oracle-adaptive}
>
U_{\rm best-fixed}.
\]

### H4 — Controller captures the oracle headroom

\[
U_{\rm learned/controller}
\approx
U_{\rm oracle}.
\]

### H5 — Cross-phase synergy

\[
\Delta U_{\rm combined}
>
\max(

or at minimum the combined system preserves both component gains after overhead.

# 114. Failure modes

## 114.1 Recall@M gap is small

Then the source-aware selector has little headroom.

Action:

- remove the source selector as a primary contribution;
- focus on long-context diffusion + adaptive budgets.

## 114.2 Source n-grams mostly help CNN/DM only

Then the idea is dataset-specific.

Action:

- keep n-grams as an optional expert/gate rather than central contribution;
- investigate whether entities/numbers provide cross-dataset gains.

## 114.3 Source bias hurts abstractive generation

Action:

- stronger learned gate;
- require source evidence margin;
- set \(g_j=0\) below a confidence threshold;
- never allow source n-gram to introduce candidates outside diffusion Top-\(M\).

## 114.4 Survival is poorly calibrated

Action:

- temperature/isotonic calibration;
- use stronger features;
- train on more on-policy traces;
- use conservative lower confidence bounds in the controller.

## 114.5 Adaptive policy fragments batches

Action:

- shrink profile set;
- round \(K_v\);
- apply queue-aware tie-breaking;
- increase preference for AR under high concurrency.

## 114.6 Long-context memory retrieval overhead dominates

Action:

- fix \(R\);
- cache retrieval results across several rounds;
- use source chunk descriptors only;
- remove adaptive source retrieval if it does not improve E2E.

## 114.7 Draft model becomes too large

Action:

- reduce draft layers before reducing selector/survival quality;
- benchmark depth vs accepted-tokens/ms;
- consider narrower internal width only after same-width V1 is stable.

# 115. Safe-degradation requirements

SyncSpec should fail gracefully.

1. If no source n-gram match:
   \[
   g_j\rightarrow0
   \]
   and selector behaves like local DFlash2-style selection.

2. If survival is low:
   choose small \(K_v\).

3. If pre-draft utility is low:
   choose AR.

4. If long-memory retrieval fails:
   drafter still has current target features and recent target hidden states.

5. If batching becomes compute-bound:
   profile tables should naturally reduce speculative budgets or select AR.

This is necessary for robust cross-domain deployment.

# 122. Recommended immediate next steps

Before training the full long-context drafter:

1. freeze the current method design at this revision;
2. choose the development target pair;
3. implement a trace collector for DFlash/DFlash2;
4. run P0 Recall@M analysis;
5. build source n-gram index and run P1/P2 without training;
6. profile \(T_V(K,L,B)\) and run adaptive-budget oracle P3/P4;
7. only if these gates pass, create Stage-0 target trajectories at scale;
8. train selector before retraining the entire diffusion backbone;
9. train survival head from actual on-policy verification traces;
10. integrate the two-level \(K_d/K_v\) controller;
11. then invest in the long-context source-memory drafter.

This order minimizes GPU risk while preserving the strongest possible paper story.

# 123. Reference anchors for this design

The living specification draws on the following established directions and should keep them explicitly separated from SyncSpec's own proposed contributions:

- **DFlash: Block Diffusion for Flash Speculative Decoding** — parallel block drafter conditioned on target features.

- **DSpark** — diffusion drafter with additional local dependency/confidence mechanisms.

- **SSSD** — cheap n-gram/pattern-based speculative proposals and hardware-aware practical SD.
- **On-the-Fly Adaptive Speculative Decoding** — runtime adaptation of speculation window/model.
- **Speculative Decoding: Performance or Illusion?** — verification bottleneck, acceptance variability, and production-grade batch sensitivity.
- **EDSD** — entropy as a unified signal for draft-model alignment/training design.
- **DistillSpec** — target-draft alignment and model-generated/on-policy distillation principles.

When the design evolves, this section should be updated before making novelty claims.
