\begin{abstract}
Long-document text summarization presents a profound computational challenge for autoregressive Large Language Models (LLMs): while the input source length often spans thousands of tokens ($L_{\mathrm{source}} \gg L_{\mathrm{target}}$), the output generation remains memory-bandwidth bound. Over the past three months, we investigated acceleration techniques for this workload with a focus on Qwen3-4B. We established a unified evaluation across leading speculative decoding baselines (EAGLE-3, DFlash, Domino, and DSpark) spanning both vLLM and FlashAttention-4 (FA4) runtimes, across English benchmarks (GovReport, QMSum, Multi-News, LCC, RepoBench-P) and Vietnamese summarization datasets (VietNews, WikiLingua, ViMs, VLSP). 

Crucially, our empirical analysis uncovers two foundational bottlenecks: (1) \textit{the tree verification penalty}, where non-linear verification graphs encounter severe latency regressions under vLLM's paged memory batching, and (2) \textit{context-induced speculative drift}, where speculative acceptance rates ($\tau$) degrade substantially as prompt length scales from 2k to 16k tokens. Motivated by these insights, we position a lightweight, \textbf{Training-Free Speculative Decoding} framework as our primary proposed method. This report consolidates empirical findings, diagnoses failure modes of trained drafters, and outlines the architectural blueprint for our training-free method.
\end{abstract}

\section{Introduction}

The demand for long-context language modeling has surged, especially in document summarization, legal contract analysis, and multi-meeting synthesis. In these scenarios, the input prompt comprises thousands of source tokens, while the target summary is comparatively compact ($L_{\mathrm{source}} \gg L_{\mathrm{output}}$). During autoregressive decoding, every output token requires loading billions of parameters and a massive Key-Value (KV) cache from High Bandwidth Memory (HBM) into SRAM, rendering generation heavily memory-bandwidth bound.

To alleviate this latency bottleneck, \textit{Speculative Decoding} \citep{leviathan2023fast,chen2023accelerating} has emerged as a promising paradigm: an auxiliary, lightweight draft mechanism proposes candidate token sequences, which the target LLM validates in parallel within a single forward pass. State-of-the-art approaches like EAGLE-3 \citep{li2024eagle} and DFlash \citep{zhang2024dflash} have demonstrated notable speedups on standard short-context generation benchmarks.

However, applying speculative decoding to \textbf{long-context text summarization} introduces unique systems and algorithmic complexities:
\begin{enumerate}
    \item \textbf{High Retraining Cost}: Existing high-performance drafters require extensive pre-training or fine-tuning paired with each specific target model and vocabulary, limiting agility.
    \item \textbf{Context Scaling Degradation}: When the prompt length scales up to 16k tokens, speculative acceptance lengths decay significantly across multiple model families.
    \item \textbf{Serving Engine Incompatibility}: Tree-based verification algorithms that perform well in isolated PyTorch execution suffer noticeable throughput degradations when deployed on production serving engines (e.g., vLLM) due to paged memory fragmentation.
\end{enumerate}

\section{Background and Related Work}

\subsection{Speculative Decoding Paradigms}
Speculative decoding breaks the serial nature of autoregressive generation by using a draft mechanism to propose $\gamma$ tokens, which are verified simultaneously by the target model:
\begin{equation}
    \tau = 1 + \sum_{i=1}^{\gamma} \prod_{j=1}^{i} \alpha_j
\end{equation}
where $\tau$ is the average acceptance length and $\alpha_j$ is the acceptance probability of the $j$-th candidate token.

\paragraph{Model-Based Drafters (EAGLE-3)}
EAGLE \citep{li2024eagle,li2024eagle2} utilizes an auto-regressive draft head trained on top of the target LLM's feature space, predicting future token representations with high accuracy.

\paragraph{Block Diffusion / Parallel Drafting (DFlash)}
DFlash \citep{zhang2024dflash} replaces autoregressive drafting with a non-autoregressive block proposal, predicting an entire chunk of tokens in one shot to reduce proposal latency.

\paragraph{Tree-Based Verification (Domino, DSpark)}
To maximize candidate coverage, modern methods structure draft proposals as candidate trees rather than linear chains. The target model evaluates the tree using custom attention masks.

\subsection{Orthogonal Approaches: KV Cache Management}
A distinct line of research focuses on KV cache compression and sparse attention (e.g., FastKV, SnapKV, StreamingLLM). While these techniques effectively reduce GPU memory footprint, they address capacity rather than decoding step latency. In this work, we focus squarely on \textbf{speculative decoding acceleration}, treating memory-management techniques as orthogonal system optimizations.

\section{Empirical Analysis and Research Insights}
\label{sec:insights}

Prior to finalizing our algorithmic formulation, we conducted extensive probing into the inference dynamics of Qwen3-4B on long-context summarization workloads. Three central insights emerged:

\subsection{Insight 1: Grounding vs. Abstraction Computation Heterogeneity}
Long-document summarization exhibits marked computation heterogeneity across decoding timesteps:
\begin{itemize}
    \item \textbf{Source-Grounding Phase}: When extracting facts, entities, or key numbers, the target model's attention sharply focuses on sparse source positions. Drafters often lack the global receptive field to anticipate these tokens, causing abrupt speculative rejections.
    \item \textbf{Abstractive / Connective Phase}: When generating syntactic connectors, structuring phrases, or fluent transitions, predictions are highly predictable, yielding long consecutive accepted runs ($\ge 4$ tokens).
\end{itemize}
Treating all decoding steps with a uniform speculation budget $\gamma$ incurs wasted compute during grounding transitions.

\subsection{Insight 2: The Tree Verification Bottleneck in Serving Engines}
As observed in our empirical evaluation (Tables~\ref{tab:vllm_english} and \ref{tab:vllm_vietnamese}), tree-based speculative verification exhibits a sharp discrepancy between isolated environments and production serving engines:
\begin{quote}
    \textit{Tree-based verification methods encounter severe efficiency bottlenecks under vLLM's paged memory batching, despite favorable acceptance lengths in standalone runtimes.}
\end{quote}
Under vLLM's PagedAttention \citep{kwon2023efficient}, dynamic branching trees disrupt contiguous memory access and batching coalescing, transforming theoretical verification parallelism into memory-access overhead. This motivates prioritizing \textbf{flat or engine-friendly verification topologies}.

\subsection{Insight 3: Performance Decay Across Context Bins}
Comparing performance across prompt lengths ($0\text{--}2\text{k}$ up to $12\text{--}16\text{k}$ tokens in Tables~\ref{tab:vllm_bins} and \ref{tab:fa4_bins}):
\begin{itemize}
    \item At short contexts ($0\text{--}2\text{k}$), DFlash achieves up to $2.35\times$ speedup on vLLM and $2.34\times$ on FA4.
    \item At extended contexts ($12\text{--}16\text{k}$), speedup falls to $1.56\times$ on vLLM and $1.42\times$ on FA4.
\end{itemize}
The expanded KV cache increases the memory transfer cost per verification forward pass, which penalizes rejected speculations far more severely at 16k than at 2k context.

\subsection{Zero-Training Drafting Mechanism}
Rather than training a separate parameter-heavy drafter for each model family, our method extracts candidate proposals directly from the target model's prompt context and early representations. By leveraging prompt-matching heuristics and lightweight representation projections, we eliminate the substantial computational overhead of training specialized drafters.

\subsection{Dynamic Speculation Horizon}
To mitigate the context-scaling degradation identified in Insight 3, we formulate an online adaptive gate:
\begin{equation}
    \gamma_t = f\Big(\mathcal{H}(y_{<t}),\, |\mathrm{prompt}|,\, \mathrm{state}_t\Big)
\end{equation}
where $\mathcal{H}$ measures target confidence/entropy. When entering high-uncertainty source-grounding tokens, $\gamma_t$ is conservatively reduced to prevent costly rejected passes. Conversely, during syntactic generation, $\gamma_t$ expands to capture high-throughput speculative runs.

\subsection{Flat, vLLM-Compatible Verification}
To resolve the engine penalty observed in Insight 2, our framework avoids irregular tree graph structures. Candidate sequences are organized into linear or shallow vector batches that execute efficiently within vLLM's continuous batching scheduler.

\section{Experimental Evaluation}

\subsection{Experimental Setup}
\paragraph{Backbone Model}
All experiments are conducted using \textbf{Qwen3-4B} (\texttt{Q3-4B}) under greedy decoding (temperature $=0$).

\paragraph{Hardware \& Serving Backends}
We evaluate across two primary computational configurations:
\begin{itemize}
    \item \textbf{vLLM Serving Backend}: Evaluated at batch size 100 with maximum output length 512 tokens.
    \item \textbf{FlashAttention-4 (FA4) Backend}: Evaluated with 8,192 input tokens and 512 output tokens.
\end{itemize}

\paragraph{Datasets}
\begin{itemize}
    \item \textbf{English Long-Context}: GovReport, QMSum, Multi-News, LCC, and RepoBench-P.
    \item \textbf{Vietnamese Summarization}: VietNews, WikiLingua, ViMs, and VLSP.
    \item \textbf{Length Bins}: Evaluated in five intervals: Bin 1 ($0\text{--}2\text{k}$), Bin 2 ($2\text{--}4\text{k}$), Bin 3 ($4\text{--}8\text{k}$), Bin 4 ($8\text{--}12\text{k}$), and Bin 5 ($12\text{--}16\text{k}$).
\end{itemize}

\paragraph{Key Observations on Context Scaling}
\begin{enumerate}
    \item \textbf{EAGLE-3 Cliff on FA4}: EAGLE-3 demonstrates a steep drop-off at Bin 5 ($12\text{--}16\text{k}$), where $\tau$ collapses to 1.330, and speedup drops to $0.991\times$ (highlighted in soft peach as slower than Vanilla AR). This reveals that feature-level drafter heads struggle with accumulated position and attention drift across very long sequences.
    \item \textbf{Persistent DSpark Robustness}: DSpark maintains superior acceptance ($\tau = 2.98$ at Bin 5) and delivers $2.16\times$ on vLLM and $1.88\times$ on FA4, demonstrating that multi-candidate diversification better tolerates context expansion.
\end{enumerate}

\section{Discussion and Next Milestones}

    \item \textbf{Eliminating Drafter Training}: Training auxiliary draft models for each LLM introduces friction and fragility under context shifts. A training-free paradigm offers higher generalizability across domains.
